Core hooks are the existing portal route and the links in
`templates/developer_tools.html` and `templates/_app_menu.html`. The service is
imported lazily by the route; app boot and ingestion do not import the adapter.
Training acquisition consumes existing Source/evidence/citation/supersession
interfaces and their authorization gates. It does not redefine those objects.

Future disablement: gate route registration/access and both navigation entries
with one default-preserving extension setting, isolate plugin imports, and test
boot, ordinary ingestion/perception and unrelated project operations with that
setting disabled. Ensure the optional exporter is not invoked by core startup.
No physical unmount or new setting is implemented in this tranche. Disablement
has **not** been proved merely by documenting this plan.

Plugin artifacts must stay namespaced and provenance-bearing. Plugins may not
monkey-patch core, silently write core records, bypass permission/approval gates,
or become required by unrelated workflows. Shared diagnostic consumers should
consume this adapter's read model; the Gym must not own relational truth.
