# rebuild-static-preview — regenerate and serve the static UI snapshot

## What this produces

A fully static, non-interactive HTML snapshot of representative Archiosk
screens (home, login, upload, projects, a populated dashboard, and four
Case Workspace variants), built by driving the *real* Flask routes
through the test client — not hand-authored fixture HTML — then
neutralizing every form/link that isn't a captured static page. This is
what gets uploaded to `archiosk.com/beehive-preview/`; it is never the
live application.

Source lives in the repo at `tools/static_preview/` (not the session
scratchpad — it used to live there, which meant it could vanish between
sessions). Generated output lives under `tools/static_preview/build/`,
which is git-ignored; nothing here is committed.

## Procedure

1. Run the two build steps from the repo root, in order:

   ```bash
   ./venv/Scripts/python.exe tools/static_preview/build_preview.py
   ./venv/Scripts/python.exe tools/static_preview/postprocess.py
   ```

   `build_preview.py` seeds a synthetic project through real routes and
   captures raw HTML into `build/_raw/`. `postprocess.py` turns that into
   the deployable `build/site/` (rewrites navigation to relative
   filenames, copies the current `static/css/main.css` + JS unchanged,
   injects the "STATIC PREVIEW" banner). The banner's commit label is
   read live from `git rev-parse` — including an "+ uncommitted changes"
   suffix when the tree is dirty — so it never needs manual editing.

2. Serve it locally. Kill any previous instance first (same reasoning as
   `restart-app`: don't let a stale server keep answering from an old
   build):

   ```powershell
   Get-CimInstance Win32_Process -Filter "name='python.exe'" |
     Where-Object { $_.CommandLine -like '*http.server*' } |
     ForEach-Object { Stop-Process -Id $_.ProcessId -Force -ErrorAction SilentlyContinue }
   Start-Process -FilePath "C:\Python314\python.exe" `
     -ArgumentList "-m","http.server","8642","--bind","127.0.0.1" `
     -WorkingDirectory "<repo>\tools\static_preview\build\site" -WindowStyle Hidden
   ```

3. Verify before telling the user it's ready:

   ```bash
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://127.0.0.1:8642/
   ```

## Uploading the result

Uploading `build/site/` to the real host (SFTP to `archiosk.com`) is a
**separate, explicit action** — never do it as an automatic continuation
of rebuilding, and never as part of this skill. It requires host
credentials; if the user supplies them in chat, follow the
credential-handling rule in `CLAUDE.md` (transient file outside the
repo, deleted immediately after use, never echoed back) — don't invent
a different approach in the moment.

## Don't

- Don't hand-edit anything under `build/` — it's fully regenerated by
  step 1 every time and isn't version-controlled.
- Don't skip regenerating after a template change — only CSS/JS changes
  are picked up by re-running just `postprocess.py`; anything that
  changes what a page *renders* (templates, route logic) needs
  `build_preview.py` re-run too, since that's what captures the HTML.
