{# CLAUDE-ICON-UNIFY-01 — one place that names the canonical ARCHIOSK icon. WHY THIS POINTS AT static/app-icon.svg AND DOES NOT COPY IT The brief asked for the canonical vector to be saved as `static/img/archiosk-icon.svg`. That would have made things worse, not better: `static/app-icon.svg` is GENERATED by `tools/render_app_icon.py` from a single centreline definition, together with every PNG a home screen requests, and `tests/test_mobile_pwa_icon_01.py` asserts the committed file still matches what that generator produces. A hand-saved copy under `static/img/` would be a second file the generator does not know about. The next time anyone runs the tool, the copy silently becomes the old mark — which is exactly the drift this component exists to end. So there is one canonical file, it stays where its generator writes it, and this macro is the one place its NAME appears. Deliberately an , not inline SVG: the asset is a self-contained tile carrying its own rounded ground and its own palette. Inlining it to tint it with currentColor would fork the brand into a third appearance that disagrees with the home-screen icon and the landing page, which are the same file.
