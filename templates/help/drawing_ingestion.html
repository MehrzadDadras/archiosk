Drawing ingestion & baselines

Getting an issued set in cleanly, so that what Archiosk holds matches what the project was actually issued.

Export vector, not raster

A scanned or rasterised PDF is a picture of a drawing. Its text cannot be read, its geometry cannot be measured, and a tag on it cannot be bound to a row in a schedule. A vector PDF keeps text as text and lines as lines, and everything downstream depends on that difference.

From Revit:

  • Print / Export to PDF using a vector-capable printer, not "Raster processing".
  • Set Raster quality to its lowest usable setting — it governs only genuinely raster content, and a high setting can push whole views through the raster path.
  • Leave Hide scope boxes / Hide crop boundaries on so datum lines are not confused with drawn geometry.
  • Export sheets, not views, so the title block and sheet number travel with the drawing.

From AutoCAD: plot to DWG To PDF.pc3 rather than a print-to-image driver, and keep lineweights on. If the result has no selectable text when opened in a PDF reader, it went out as raster and should be re-plotted.

The quickest check: open the PDF and try to select a sheet number with the text cursor. If it highlights, it is vector.

What a baseline is here

A baseline is simply the issued set you are treating as authoritative at a point in time. Archiosk does not have a separate "baseline" object — it has Sources with recorded provenance and content digests, and a baseline is the state of that register after you have reconciled it against the issued folder.

The practical consequence: establish the register from the issued set first, before adding sketches, markups or working files. Then every later comparison has something honest to compare against.

Organising a multi-discipline package

Keep one folder per discipline under a single issued root, and keep the issue date or revision in the folder name rather than only in the filenames. Reconcile compares by path as well as content, so a stable folder structure is what lets a re-issue read as modified rather than as a pile of unrelated new documents.

Do not flatten disciplines into one directory to "make uploading easier". The structure is evidence about how the set was issued, and flattening discards it permanently.

When you are ready to compare a folder against what is registered, see What is Reconciliation?. For accepted formats and how large files are handled, see File types & limits.

What uploading a drawing does not do by itself

Registering a drawing makes it a governed Source with provenance and a content digest, and makes its text readable as project evidence. It does not automatically build a 3D model, detect clashes, or align disciplines. Those are separate capabilities — some built and reached through their own surfaces, some not built at all — and none of them happen as a side effect of an upload.
