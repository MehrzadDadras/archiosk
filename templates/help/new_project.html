New Project

What New Project does

New Project creates a governed project record and connects its first documents to Archiosk. Use a folder connection for a project set or Upload File for one founding document.

Your role and project position

  • Client / Owner: procures design or construction services.
  • Lead Design Consultant: leads design coordination for the party that retained the consultant.
  • Subconsultant / Specialist Consultant: provides a specialist discipline through the consultant chain.
  • Prime / Design-Builder / GC: leads the delivery or construction team.
  • Subcontractor / Trade Bidder: provides trade work through the delivery chain.

Project position records where you sit in the procurement chain. Who engaged you? records the relevant upstream relationship for the selected position. Only that position's applicable control is enabled.

GO uses project position to decide which questions and evidence to bring forward. It does not determine your contract, authority, entitlement, or document authority. Confirmation is required because project position becomes immutable after project creation.

How the page is arranged

New Project asks in a fixed order: Your identity (your name and your role), Company identity (your position on this project), Project identity (project name and acronym), Upload Project Folder, Upload File, and Composer last.

Your identity and Project identity are framed together because each pair is one answer: who you are, and what this project is called. The grouping is presentational — every field behaves exactly as it does elsewhere.

Project name

Use the project name your team will recognize. Project names must be unique. If no name is entered, Archiosk derives one from the selected file or folder; a duplicate name is refused with Project name already exists.

Uniqueness is checked against every existing project's current effective name, not just its original filename, so renaming an earlier project does not free up its old name by accident.

Acronym

Use 3 or 4 letters. The acronym becomes the short project identity used in references such as ABCD-T014.

You can accept the acronym derived from the project name or type your own. After project work is filed under it, the acronym persists so existing references do not change.

Document connections and source domains

Every explicitly connected source retains one source domain. Source domain describes where material came from; it does not determine authority.

  • Client Data Room — CLIENT_ISSUED: requirements and information received from the engaging party. An RFP, Addendum, or Project Agreement may govern differently from background reports, minutes, or site-visit records; receipt alone does not make every item equally authoritative.
  • Your Workspace — TEAM_WORKSPACE: team-created proposals, designs, coordination records, RFIs, and submissions. Team work does not become evidence of what the Client required.
  • External References — EXTERNAL_REFERENCE: codes, standards, guidance, and other reference material. External material does not become project-issued authority by being connected.

Existing sources without a recorded domain remain UNKNOWN legacy sources; they are not silently reclassified.

Upload Project Folder

The browser supplies files only from the folder you select and preserves their relative paths. Choose the matching source-domain button first. Archiosk shows the selection and connects it only when you submit.

Folder registration accepts PDF, DOCX, TXT, CSV, MD, and XLSX. A principal document is required to establish the project and must be PDF, DOCX, TXT, CSV, or MD; spreadsheets can be registered but cannot be the founding document. If one eligible top-level document exists it is proposed visibly; otherwise you select the principal document.

The deployment's upload-size limit is enforced for the request. Unsupported files are reported and skipped rather than registered as unreadable sources.

Upload File

Upload File accepts PDF, DOCX, TXT, CSV, or MD, stores a project copy on Archiosk's server, and parses supported content. When no active connection supplies a source domain, the source remains UNKNOWN rather than being silently classified. The file picker displays the active deployment limit when a file is too large.

Choosing more than one file. Choose File accepts a multiple selection, and each chosen file becomes its own row. Choosing again adds to the list rather than replacing it, so you can pick from several folders in turn. A file already staged is not added twice. Each row's × removes only that file, and Upload Files stays unavailable while no file is staged.

With one file staged, the page behaves exactly as a single upload always has. With more than one, the first file in the list establishes the project and the rest are connected as additional documents; the page states which file that is before you submit. Nothing is uploaded until you press Upload Files.

Text-bearing PDFs and documents provide the strongest evidence. Images and scanned drawings may not contain readable text; native images are not accepted by this founding-file control. XLSX can be registered through a supported folder or project document path but cannot establish a project by itself.

See File types & limits and Drawing ingestion & baselines for detailed limitations.

Composer

Use Composer at the bottom of New Project to ask GO about the page and its fields. It uses New Project page context and does not create a project or ingest a selected file. The file picker is not a manual document-context toggle.

Composer looks and behaves the same everywhere in Archiosk — same field, microphone, Send button, spacing and keyboard rules — because every one of them is rendered from a single shared Composer. Pressing Enter sends; Shift+Enter starts a new line where the field accepts one.

No demonstration suggestions are shown. If real suggestions are available, Down Arrow selects the next suggestion, Up Arrow selects the previous one, Enter accepts it, and Escape dismisses the list. Arrow keys are not captured while suggestions are closed.

Why there is no attachment control here. Composer offers a + attachment only where an attached file has a governed home to go to — inside a project. New Project has no project yet, and this Composer answers from page context rather than reading documents, so it would have nowhere to put an attachment and nothing to do with it. The control is left out rather than shown and quietly ignored.

Long-running action status

Long-running actions show started, running, completed, failed, or cancelled with elapsed time in 00h:00m:00s format. The clock updates once per second, stops in a final visible state, and resets for the next action. It does not show fake percentage progress or estimate remaining time.
