Spin & Survival Mode

A comprehensive machine review of a project's evidence. Always explicitly triggered, never automatic.

What a Spin is

A Spin reads the evidence already in a project and characterises it as a whole. It is a deliberate act: nothing schedules one, nothing runs one in the background, and no upload triggers one. You press the button.

That is a design decision rather than a limitation. A review that ran itself would produce findings nobody asked for, attached to a moment nobody chose, and the record would not say who wanted them.

First Spin

Characterises the project as it stands. It has nothing to compare against, so its findings carry no delta classification — the surface says so plainly: “First Spin establishes a baseline — no prior state to classify against.”

Trigger: the Run First Spin button in the Toolbox. Available at any time.

Delta Spin

Characterises what has materially changed in project understanding since an earlier Spin. Not what changed in the files — what changed in what the project is understood to say.

Trigger: the Run Delta Spin button, which appears only once a First Spin exists. Until then the surface says “Run First Spin before Delta Spin is available.” There is no baseline to be a delta from, so the control is absent rather than present-and-failing.

Each Delta finding carries one of eight classifications, and only these eight — the engine drops anything outside the closed set rather than inventing a label:

new
Understanding that was not present before.
unchanged
Present before, and materially the same.
strengthened
Present before, now better supported.
weakened
Present before, now less well supported.
resolved
An earlier open question that now has an answer.
superseded
Replaced by a later understanding.
new_verification_gap
Something now needs checking that did not before.
indeterminate
The relationship to prior understanding could not be established. Kept as its own honest answer rather than being forced into one of the seven above.

Survival Mode

A lens, not a third kind of Spin. It is a checkbox on either button, and it changes what the same engine is looking for:

Find consequential conditions that could materially harm project success if overlooked.

An ordinary Spin characterises the project. A Survival Spin goes looking for what could hurt it. Same evidence, same machinery, a different objective added to the instruction.

Trigger: tick Survival Mode before pressing either Run button. It combines with both — a Survival First Spin and a Survival Delta Spin are both real and both useful.

It does not lower a threshold, widen a search, or make the engine more suspicious in general. The entire mechanism is the objective above being added to the pass, which is why a Survival run is not “more thorough” — it is aimed differently.

Where results appear

Spin findings render in their own clearly-labelled section and never mix into the ordinary Findings list. First Spin and Delta Spin runs stay separate from one another, and each run's classification is shown prominently rather than buried.

That separation is deliberate: a machine characterisation and a recorded project Finding are different kinds of claim, and a list that blended them would make the weaker one look like the stronger.

Which to run

Nothing has been Spun yet
First Spin. It is the only option, and it makes the baseline.
Evidence has arrived since the last Spin
Delta Spin. It answers “what is different now”.
Before a milestone, a submission, or a difficult meeting
Either, with Survival Mode ticked.
You want the whole picture again, not the difference
First Spin. Running one again re-characterises from scratch.
