Field access passes

A pass is a link. Anyone holding it has exactly the role and disciplines it was issued with, until it expires or is revoked. There is no password and no account behind it.

Roles

Five exist. Three can be issued from the access panel.

owner
Client or owner side. Reads every discipline.
engineer
Reads only the disciplines named on the pass.
trade
Narrowest. Reads only the disciplines named on the pass.
architect
Reads everything and manages passes. Not issuable from the form — a form that mints another architect pass is a privilege-escalation control wearing a form label.
platform_admin
Infrastructure and tenants. Reads no drawings at all. Managing access is not the same capability as having it.

engineer and trade must name at least one discipline. An empty scope could mean “all” or “none”, and that is not a thing to resolve later.

What a scope actually blocks

Discipline scope is enforced where the bytes are served, not on the page that lists them. A structural pass asking for an architectural sheet is refused with a 403, and the sheet is never listed for them in the first place — a sheet mark is itself information.

The same scope applies to anything the assistant is asked. Context is filtered before a prompt is built, so a boundary that holds over HTTP cannot be walked around by asking a question instead.

QR onboarding

Issuing a pass shows a Building Box field pass: a scannable code, the role, the scope, and how long is left. Hold the screen up and the trade scans it with their phone camera. No typing.

The code is shown once. Only a SHA-256 digest of the token is ever stored, so the link cannot be recovered afterwards — not by an architect, not by an administrator, not from the database. Copy it or scan it from that screen.

The code is generated on this server. It is never sent to an external image service: the payload is a live credential, and handing it to a third party would mail every stakeholder pass to a company nobody chose.

Lost a link? Re-issue it

The passes table has Re-issue QR, not “show QR”. The difference is real: the original token no longer exists to show. Re-issue mints a replacement carrying the same role, scope and expiry, and revokes the original immediately.

That is usually what you want. The reason a link needs re-issuing is normally that it went somewhere it should not have.

Rotation never extends an expiry and never widens a scope. It is a new credential, not a new grant. An expired pass cannot be rotated — issue a new one, which is a decision the form makes you make.

Revoking

Revoke now takes effect on the very next request. There is no cache and no session to wait out.

Revoked and expired rows stay in the table. It answers “who has access”; one that dropped withdrawn passes could not answer “who used to”, which is the question asked after an incident.

If the assistant stops answering

A trial project has a query allowance. When it runs out you will see:

You have run out of fuel, but the system allows you to get home safely. Contact admin for further help.

The query that used the last of it still completes in full. After that, everything except the assistant keeps working — sheets open, zoom and pan work, navigation works, and you can still escalate a question to a human. Only the model stops.
