File types & limits

What Archiosk accepts, how big it can be, and what happens to a large file on the way up.

Accepted formats

.pdf, .docx, .txt, .csv, .md, .xlsx. Anything else is refused at the point of upload rather than accepted and quietly ignored later — a Source that exists but can never be read is worse than one that was never created.

A vector PDF is worth far more here than a scanned one. Text and geometry that are still real objects can be read for spatial reference; a scan is a picture of a drawing, and a picture cannot be asked what a tag says. See Drawing ingestion & baselines for how to get one out of Revit or CAD.

How large a file can be

A single ordinary upload is capped at the deployment's MAX_UPLOAD_MB. A file above the chunking threshold is not sent as one request at all — see below — and is instead capped by MAX_CHUNKED_UPLOAD_MB, which is set far higher.

Both numbers are deployment settings rather than fixed product limits, so this page deliberately does not quote them: a number printed here that disagreed with the server would be worse than no number. The upload will tell you the real limit if you exceed it.

Large files upload in pieces

Above roughly 5 MB, the browser slices the file and sends it as a sequence of chunks instead of one request. This is automatic; there is nothing to switch on.

You will see an explicit progress bar with a percentage and a byte count, then Assembling & verifying file… while the server reassembles the pieces and checks them.

Why it works this way. One very large request occupies a server worker for its whole duration and is lost entirely if the connection drops at 90%. Chunks are retried individually, so a brief network stumble costs one piece rather than the whole transfer.

Integrity is checked, not assumed. The server computes a SHA-256 digest while it writes the reassembled file, and that digest becomes the Source's recorded hash. A file that does not assemble completely never becomes a Source at all — there is no partial document to find later and mistake for a whole one.

If your sign-in expires part-way through, the upload stops and returns you to the sign-in page rather than failing obscurely. Nothing partial is registered.

What this does not do

Chunked upload currently applies to Add documents to project (Admin → Project Data Management). The Data Room Reconcile folder picker still sends its files in a single request and is bound by the ordinary upload limit. If you are reconciling a very large issued set, add the largest documents individually first.
