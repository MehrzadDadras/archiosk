{# --------------------------------------------------------------------------- THE PLAN GEOMETRY, DEFINED ONCE. This macro is what makes the `live` miniature basis structurally true instead of merely asserted. The full canvas and the Page-Field miniature both call it, so the miniature is not a picture of the drawing and cannot drift from it - there is only one definition, rendered at two sizes. A change to a wall here moves in both places in the same commit, which is precisely the property a captured thumbnail cannot have. `uid` exists because SVG ids are document-global: rendering the same markup twice on one page with a fixed id would silently make the second instance reference the first one's pattern. Every id the macro emits is suffixed. `view` crops the viewport WITHOUT touching the geometry. The sheet is 1000x700 but the building only occupies x 90..910, y 70..630, so a miniature that reuses the full sheet spends roughly a fifth of its width on blank margin - at 171px that is the difference between reading as a floor plan and reading as a diagram. Cropping changes which part of the drawing is visible, never what the drawing is, so the `live` claim survives it: still one definition, still not a copy. The crop is declared in routes/calm_lake_prototype.py as MINIATURE_VIEW, because the pin coordinates have to be projected into the same window and a constant that two files must agree on belongs in exactly one of them. `detail` drops the annotation layer (grid references, dimension ticks) at miniature scale, where it would collapse into noise. Geometry - walls, rooms, corridor, stair, ducts - is identical in both, because that is what makes the face recognisable as THIS sheet rather than a generic plan. --------------------------------------------------------------------------- #} {% macro plan_geometry(uid, css_class, label, detail=true, view="0 0 1000 700") %} {% endmacro %}
