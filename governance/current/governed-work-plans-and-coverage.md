# Governed work plans and requirement coverage

This extension follows the prior owner mapping in
`work-plan-capital-transaction-mapping.md`. It adds no evidence store, transaction
database, matching engine or frontend framework.

## Procedure and proof

`InvestigationStep.governed_work_plan` stores intended procedure. The original
step is retained; execution, dependency revisions and results append linked
steps. Plans carry no authority and are excluded from evidence fingerprints.
The workspace's existing optimistic version check prevents concurrent starts.
Repeated execution of the same plan is refused. Current permissions, lifecycle,
admission and source applicability remain the executor's responsibility.

The shared attention route declares a plan, renders it through the existing
template, then automatically submits the retained inputs to its existing
dispatcher. CSRF/session values are not retained. Unsupported inputs and
destructive operations are rejected by this bounded procedure adapter. JavaScript
uses the form action attribute because the existing input named `action` shadows
the DOM property. Non-JavaScript callers retain the procedure and execute through
the same route; the two-request browser flow supplies pre-execution display.

Reload never starts, resumes or retries a plan. A changed available premise
snapshot produces a revision, and the real resolver's explicit scope-crossing
dependencies are copied into the plan history after the result is committed.
These records describe execution; they do not interpret or promote evidence.

Completion is a read-only conjunction of actual invocation/return, retained
result references, source/claim lineage, consumed-and-surfaced UI trace, and an
applicable successful frozen-tree test receipt. Until all proofs exist the status
remains PARTIAL; a successful HTTP redirect is insufficient. Domain refusal is
retained separately. Runtime trace locators point to existing operational records
and remain outside project evidence. `tools/qualify_go_runtime.py` runs the actual
full gate and retains its receipt through `runtime_observation`; it cannot import
an old log or accept a caller's PASS flag. Test fingerprints normalize Git text
checkout line endings only. Uploaded source hashes and protected byte pins retain
their existing, separate integrity rules.

## Explicit requirement coverage

The existing `run_role_composition` accepts optional typed coverage policies.
The existing `cover_requirements` enumerates increasing cardinality and consumes
the configuration checks; it preserves all equally minimal alternatives. The
extended policy path is bounded to eight participants and sixteen selected
requirements. No average score chooses a winner. Removing each participant
exposes the coverage lost, and every smaller tested combination remains
inspectable. Collective required coverage is distinct from individual hard
eligibility. Existing unselected mandatory candidate conditions remain explicit
scope-crossing dependencies and cannot be bypassed by the coverage selection.

The same normalized comparison results supply the assignments. Missing/stale
premises remain unresolved; a hard conflict requires a positive failed predicate.
Known proper quantity subsets may be partial. Addition requires compatible units,
property/scope/qualifiers and an explicit source-anchored combination proposition
covering the actual participants. Authority, currentness, identity, geography,
sector and mandate cannot be summed. A combination basis is itself a proposed
interpretation, so these extended coverage runs are EVALUATION_INPUT and factual
configuration remains UNRESOLVED. Coverage never establishes partnership
compatibility, commitments or an actual JV. Positive verified compatibility and
transaction-history admission are later work under the same programme.

The shared matcher now distinguishes unknown dimensions from known partial fit.
A missing mandatory or optional premise cannot become PARTIAL merely because
another criterion matches. Positive mandatory failure still dominates. Known
optional non-matches may produce PARTIAL. Retained earlier analyses are not
rewritten; explicit re-analysis applies the current rule.

## UI and validation surfaces

The existing attention page exposes the coverage matrix, minimum combinations,
roles, compatibility uncertainty, failed smaller configurations, provenance and
removal sensitivity. Existing controls remain available while the extension is
qualified. Result-first reports precede collapsed plan/technical history. Report
styles use the existing external stylesheet, respecting the current CSP.

Survey Evaluation includes one-, two-, three-party, equal-minimum, supported
addition and unsupported-addition cases through these same owners. They are
explicitly evaluation data, never production investor truth. The browser verifier
supports `--work-plans` and `--coverage-games`; its default workflow also exercises
existing source corrections, professional review, matching and composition.

Focused regressions live in `test_go_work_plans.py`,
`test_work_plan_qualification.py`, `test_requirement_coverage.py`, and the existing
matching/composition/report/runtime suites. Successful local browser runs do not
substitute for an authenticated production browser session.
