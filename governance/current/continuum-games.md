# Continuum evaluation games

The existing Survey Evaluation case selector now includes twelve GO review games.
They use the same isolated evaluation registry mechanism as the Survey controls.
Controlled PDFs are retained and their real text is extracted with PyMuPDF into
ordinary Source/page/region/EvidenceItem records. Explicit evaluation premises
configure the existing attention, professional review, coverage and constraint
owners. No expected outcome is supplied to a runtime resolver.

Cases cover required-but-unconnected detail, legitimate independence, unique
coverage, one typical representation covering two reviewed conditions, missing
section, missing discipline, specification without manifestation, drawing without
support, compatible scalar intervals, incompatible intervals, first limiting
constraint and an air-control label without established continuity/performance.

Selecting a game invokes the real owners and opens the existing attention UI.
The UI exposes retained inputs, source jumps, coverage, qualifications and actual
muscle results. Reload does not run a producer. Subsequent investigation uses the
ordinary review and constraint forms. Survey-only confirm/evaluate commands cannot
be applied to these review runs. Archive, project and source identity owners are
unchanged; these isolated cases never enter the normal project registry.

These are text fixtures supplying explicit class, resolution and applicability
premises. They are not physical detail drawings, automated engineering verification
or human project approvals. All inputs and results preserve EVALUATION_INPUT.
No populated project is altered. Full project inventory, semantic redundancy,
interpretation drift and the remaining master programme are not claimed complete.

Qualification: tests/test_continuum_games.py covers the real Flask creation path,
owned invocation, persisted results, source/record preservation on Reload and
Survey-action refusal. The existing Survey roundtrip test retains all its original
Survey cases; these new non-Survey cases have their own consumer contract.
tools/verify_source_review_ui.py --games exercises each case through real browser
forms, follows source jumps and retains runtime references. Authenticated live
browser verification uses only an existing human-issued verification URL.
