# Typed view commands

Document Shop Ask GO can propose ROTATE_VIEW, MIRROR_VIEW, FIT_VIEW and
ALIGN_NORTH_UP using the existing model call and an enabled capability catalogue.
The strict command contract accepts no caller-selected actor, project, source or
filesystem path. Execution reloads the workspace and checks current ownership,
active lifecycle, full visibility and source membership. Existing DerivedView
records own the result; no source, evidence or analysis is rewritten.

The result page displays retained derivatives, matrices, hashes, lineage and
qualification. GET Reload and image retrieval never invoke a transform. The image
route enforces the same owner and lifecycle boundary and validates artifact hashes.

North-up requires the existing true-north resolver to establish an applicable
direction. It remeasures that arrow against the actual retained source. Native
single-page vector PDFs can supply the document frame; embedded raster PDFs and
multi-page inputs without explicit page selection refuse. Photographic-frame
uncertainty remains unresolved. Successful display alignment adds no metric,
physical, legal or survey authority. Mirrored source text remains mirrored and is
labelled accordingly; readable annotation re-rendering is not yet implemented.

Focused tests cover actual route invocation, source preservation, read-only
Reload, cross-user access, lifecycle changes and stale directional measurements.
The local browser verifier drives Ask GO through the real route and executors
with a controlled intent-provider response, explicitly labelled as such. It is
not live natural-language provider proof. Production browser verification still
requires the existing human-issued verification access; agents do not mint it.

This bounded catalogue does not claim completion of all Action Registry classes,
general project command execution, view-normalized semantic comparison or the
remaining master programme. Those continue through the existing owners.
