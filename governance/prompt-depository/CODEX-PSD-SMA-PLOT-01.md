## Governing interpretation

This record is an oracle-side description of a blind proving experiment. It is not a Source, EvidenceItem, Requirement, Finding, Spin input, hidden model instruction, or project document. It must never be copied into either the Owner or Proponent corpus.

The general capability under test is:

> A consequential project proposition depends on an unresolved external-authority condition; investigate the governing authority.

Smoke is the proving case, never the routing rule. Success requires GO to recognize that project evidence alone is insufficient, request governed external authority, traverse verified applicability conditions and exceptions, and ground the resulting finding in both admitted authority and visible project evidence. Keyword recognition, model recollection, oracle leakage, or a smoke-specific trigger does not satisfy the experiment.

## Blindness and oracle boundary

- Owner-private Spin findings, working drafts, this plot, oracle answers, hidden OBC conclusions, and unreleased reconstructed consultant material never enter the Proponent project.
- The Proponent project begins as a fresh, separately governed project containing only the formally published procurement package.
- Later Proponent design evidence enters only at its scheduled phase.
- Official OBC material remains external regulatory authority; consultant Code reports and matrices remain consultant interpretation/design response.
- Without admitted verified OBC evidence, GO may identify an unresolved regulatory dependency but may not cite a remembered clause as authority.
- The oracle evaluates discovery from outside the project. It never supplies undisclosed evidence or expected conclusions to GO.

## Staged experiment

1. Finalize the credible Owner RFP.
2. Run and review the Owner First Spin.
3. Publish/freeze/export the governed procurement package.
4. Create a fresh Design-Builder/Proponent project.
5. Import only the published package.
6. Run the blind Proponent First Spin.
7. Introduce the credible constructed Proponent design response.
8. Run Delta Spin.
9. Observe whether GO identifies the unresolved external regulatory dependency.
10. Permit separately authorized OBC Airlock traversal.
11. Assess whether GO produces an evidence-grounded finding.

Later, separately authorized stages may introduce consultant Code Report/OBC Matrix evidence to test interpretation checking, contradiction, comparison, maturity, and convergence.

## Success and finding discipline

Success requires all of the following:

- a consequential design proposition is recognized;
- project evidence alone is recognized as insufficient;
- external regulatory authority is requested through the governed Airlock;
- applicability is tested against actual project facts, including qualifications, exceptions, and alternative paths;
- the result cites verified authority and project evidence;
- the response is characterized as demonstrated, not demonstrated, conflicting, unresolved, or supported by an accepted alternative path as the evidence warrants.

Where absence has not been proven, use **not demonstrated** rather than automatically claiming **not provided**. The inspectable reasoning grammar is:

> Regulatory requirement → project condition → Proponent response → evidence status → finding → required resolution
