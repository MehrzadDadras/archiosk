## Confirmed principles

- Compose games from existing primitives before inventing new primitives.
- Select games in response to evidence, scope, relationships, uncertainty, project maturity, and the purpose of the current investigation.
- Games may operate sequentially or recursively, but must remain bounded and inspectable.
- The same primitive can support many different games.
- The same game may be used differently in different Project Worlds or Modes.
- Games help GO investigate; they do not predetermine what GO must believe.
- The Product Owner should be able to understand why a game ran without exposing private chain-of-thought.

## Exact prompt text

```text
A Spin-Game is a bounded investigative composition made from reusable GO primitives and review capabilities.

It is not a fixed checklist, not a single static mega-prompt, and not a replacement for Spin itself.

A discovery in one game may legitimately trigger another game when the evidence warrants following the consequence.

**Trigger → Game → Probe → Evidence → Relationship → Follow-on Game**

**Before creating a new primitive, search for a useful composition of existing primitives. When a genuinely missing primitive is discovered, build it as a small lubricated package with stable interfaces so that it multiplies what the other primitives can do.**
```
